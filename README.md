## <a id="Documentation:Development"></a> Development <sup>[⤒][Top]</sup> <sup>[⤓][Bottom]</sup> <sup>[↩][Documentation]</sup>

1. Скачать с официального сайта программу [Source 2 Viewer](https://s2v.app/) (это portable-версия, достаточно запустить `.exe`), открыть через нее оригинальные файлы игры

    1. Удалить существующую директорию `src/soundevents` из корня проекта

        > В этой директории хранятся манифесты всех звуковых файлов для игры
        >
        > Манифест - текстовый файл, в котором хранится словарь внутриигровых ивентов, которым требуется назначить звуковое сопровождение
        > ```
        > Abrams.A4.Leap.Float.Lp = 
        > {
        >   base = "Base.Ability.Ult"
        >   volume = -9.000000
        >   volume_offset_team = -6.000000
        >   volume_offset_opponent = 3.000000
        >   volume_enemy_targeting_boost = 7.000000
        >   vsnd_files = "sounds/abilities/abrams/a4_leap/abrams_a4_slam_float_lp.vsnd"
        >   vsnd_duration = 2.543424
        > }
        > ```
        >
        > Эти манифесты скрипт будет парсить, чтобы подменять в них пути к звуковым файлам и, при необходимости, подкручивать громкость, удалять/изменять неподходящие поля у конкретных внутриигровых ивентов

    2. Запустить программу ([`Source 2 Viewer`](https://s2v.app/))
    3. В меню слева сверху выбрать `File` -> `Open`
    4. В открывшемся меню выбрать файл `Steam/steamapps/common/Deadlock/game/citadel/pak01_dir.vpk`
    5. После прогрузки файлов, экспортировать директорию `soundevents` (`ПКМ` -> `Decompile & Export` -> `Ok` -> выбрать директорию `src` относительно корня проекта)
    6. Таким образом произойдет "синхронизация" (некий `git merge`) нашего аддона с оригинальными файлами игры

2. [Запустить скрипт][Documentation:Usage] (этот этап нужен, чтобы скрипт спарсил все манифесты и синхронизировал директорию со звуковыми файлами)

    1. Если в директории со звуковыми файлами есть файлы, которые больше не упоминаются ни в одном из манифестов - такие файлы будут удалены (если в процессе удаления такого мусора был удален звуковой файл, который хочется использовать где-либо в другом месте - его можно восстановить через `git` и переместить в новое место)
    2. Если в директории со звуковыми файлами для умений героев (`src/sounds/abilities`) нет какого-то файла, который упоминается в одном из манифестов героев (`src/soundevents/hero`) - такие файлы будут сгенерированы (будут созданы файлы-пустышки с одноименными названиями, но без расширения, чтобы можно было легко и удобно в будущем заменить их на настоящий звуковой файл)

        > Например, в последнем патче [зеленоликое солнышко](https://ru.wikipedia.org/wiki/%D0%99%D0%BE%D1%88%D0%B8) добавило в манифест героя `Abrams` новый внутриигровой ивент, и, соответственно, новый звук, которого не было раньше (`sounds/abilities/abrams/bimbim_bambam.vsnd`). В таком случае скрипт создаст на его месте файл-пустышку (**НЕ** настоящий звук, а просто пустой файл) без расширения (`src/sounds/abilities/abrams/bimbim_bambam`). Чтобы добавить свой собственный звук для этого внутриигрового ивента, достаточно скопировать нужный `.wav` файл в `src/sounds/abilities/abrams` и переименовать его в `bimbim_bambam.wav`. При следующем [запуске скрипта][Documentation:Usage], файл-пустышка будет автоматически удален, а настоящий звуковой файл будет импортирован в нужное место в манифесте

        > Логика генерации файлов-пустышек прописана только для манифестов героев. Звуки, которые используются в манифестах окружения, войс-лайнов, музыки не будут генерироваться автоматически, потому что одних только войс-лайнов сгенерируется раза в 4 больше, чем звуков способностей героев. Для замены таких звуков нужно будет открыть исходные файлы игры через [`Source 2 Viewer`](https://s2v.app/) (как в пункте 1), открыть там директорию `sounds`, найти интересующий звук, скопировать путь к нему (`ПКМ` -> `Copy name`) и создать в директории `src` относительно корня проекта такой же файл (скопированный путь к файлу уже содержит `sounds/`), после чего заменить его на настоящий звуковой файл `.wav` (имя должно оставаться таким же)

3. Открыть директорию `src/sounds`, заменить желаемые звуковые файлы на настоящие `.wav` (игра позволяет добавлять несколько вариантов звуков на один и тот же внутриигровой ивент - для этого нужно заменить желаемый звуковой файл сразу на несколько новых, но все такие новые файлы должны иметь одинаковые имена с суффиксом `_XX`, например, `bimbim_bambam_01.wav` и `bimbim_bambam_02.wav` вместо старого `bimbim_bambam`). Если для одного внутриигрового ивента есть несколько звуков, но они неупорядочены (`bimbim_bambam02.wav` и `bimbim_bambam_09.wav`) - можно перейти к следующему шагу, скрипт автоматически их упорядочит и приведет к (`bimbim_bambam_01.wav` и `bimbim_bambam_02.wav`)

4. [Запустить скрипт][Documentation:Usage] (на этом этапе уже будет непосредственная сборка аддона - здесь нужно обратить внимание на логи в терминале)

    - В момент, когда скрипт начнет патчить манифесты (подставлять пути к новым звуковым файлам вместо старых), появится лог `Generating sound manifests`
    - Если сразу после этого лога появятся сообщения формата `Found unconfigured sound event: Event.Name` - это значит, что **рекомендуется** добавить названия найденных внутриигровых ивентов в коллекцию (в коде скрипта есть коллекция всех внутриигровых ивентов, она существует для удобства, чтобы можно было в любой момент отредактировать, например, громкость нужного внутриигрового ивента, чтобы сделать звуки для него чуть потише/погромче)

        > Коллекция находится в файле `src/build.mjs` на строке `17`. Элемент массива (внутриигровой ивент) имеет синтаксис `[EVENT_NAME, [[VOLUME]]]` (в будущем, если будет не лень, можно будет шерить звуки внутриигровых ивентов друг другу, или переопределять их целиком, чтобы не нужно было создавать дубликаты одних и тех же звуковых файлов, а просто определить их сразу для нескольких несвязанных внутриигровых ивентов, например, и для героя, и для окружения, и для музыки сразу)
        >
        > ```js
        > const expectedSoundManifestEventMap = new globalThis.Map([
        >   ...,
        >
        >   ["Event.Name", [[0]]],
        >
        >   ...,
        > ]);
        > ```
        >
        > В этот массив нужно будет добавить все внутриигровые ивенты, которые высветились в логе (массив уже упорядочен, сначала идут герои, потом музыка, потом окружение, но если сильно впадлу думать, можно просто кинуть внутриигровой ивент в конец списка) - для каждого нового внутриигрового ивента **рекомендуется** выставить громкость на `0` (это работает, как +`0`Дб, вроде бы), чтобы сначала прикинуть, насколько звук громкий/тихий, а потом редактировать по усмотрению

    - Также может быть выведен и обратный лог формата `Found unused sound event: Event.Name` - это означает, что в коллекции внутриигровых ивентов, некоторые из них уже не используются (например, сначала добавили новый звук для второго умения героя (и добавили название внутриигрового ивента в коллекцию, как рекомендует скрипт), а потом решили перенести звук на третье умение - таким образом, второе умение снова осталось без звука, а внутриигровой ивент в коллекции остался - его нужно вручную удалить)

    - Когда манифесты пропатчены, в логи выведется информация о том, сколько манифестов изменено и сколько звуков использовано
    - Если после этого лога появятся сообщения формата `Found unused sound file: FILE` - это значит, что в директории `src/sounds` чисто технически нет лишнего мусора, но какой то из файлов не используется из-за ограничений игры. Например, если попытаться добавить несколько вариантов звука на внутриигровой ивент выпадения конкретной игральной карты у персонажа `Wraith`, будет использован только первый звук, а остальные звуковые файлы для этого внутриигрового ивента будут проигнорированы (ограничение самой игры конкретно для такого вида внутриигровых ивентов - мб [мегазаечка](https://ru.wikipedia.org/wiki/%D0%99%D0%BE%D1%88%D0%B8) пофиксит)

## <a id="Documentation:Usage"></a> Usage <sup>[⤒][Top]</sup> <sup>[⤓][Bottom]</sup> <sup>[↩][Documentation]</sup>

1. Запустить терминал (`CMD` / `PowerShell`) в корневой директории проекта
2. Вставить в терминал команду и дождаться завершения выполнения (терминал встанет на паузу и попросит нажать любую клавишу)

    ```
    node src/build.mjs & pause
    ```

    > Если вместо `&` вставить `&&`, как это было бы в UNIX*-системах, то при возникновении ошибки выполнения программы, терминал тут же закроется, не дав возможности ознакомиться с выводом (лайк [этому парню](https://en.wikipedia.org/wiki/Bill_Gates))

3. В директории `build` (если ее не было, то скрипт ее создаст) создадутся файлы

    - Директория `pak69_dir` - здесь хранятся скомпилированные ассеты (скомпилированные звуки + манифесты к ним). Она нужна скрипту для сборки аддона ([великий движок](https://en.wikipedia.org/wiki/Source_2) отдельно компилирует ассеты, а потом уже упаковывает их в общий архив, и чтобы было удобнее, делает это двумя разными программами, для чего приходится жонглировать файлами, копировать их туда-обратно, причем, зачастую в строго обозначенные директории, при отсутствии которых, компиляция просто крашнется)

    - Файлы `pak69_dir.vpk`..`pak69_XXX.vpk` - непосредственно сами файлы готового аддона (файлов несколько, потому что зачастую общий размер аддона превышает 300MB, а такой внушительный размер одного файла сможет успешно крашнуть любую Source игру с вероятностью более 99.9%)

4. Скопировать/переместить файлы готового аддона (`pak69_dir.vpk`..`pak69_XXX.vpk`) в директорию игры, где хранятся другие аддоны (`Steam/steamapps/common/Deadlock/game/citadel/addons`). Если директории `addons` нет - ее нужно создать вручную
